# Must Be The SQL — Docs Site

基于 [Docusaurus v3](https://docusaurus.io/zh-CN/docs/) 搭建的产品文档站点，**独立于业务前端工程**，对外提供产品使用教程。

> 📌 文档站点（本工程）≠ Java 后端 Swagger 接口文档。两者分开，本站可在 [API 说明](docs/api/overview) 中跳转 / 嵌入 Swagger。

## 设计基线（与产品一致）

| 项 | 值 |
| --- | --- |
| 主色 | `#5b7fd9`（`--color-primary`） |
| 字体 | `Inter`（正文） + `JetBrains Mono`（代码） |
| 明暗 | 双模式开启，默认浅色，`respectPrefersColorScheme` |
| 搜索 | 本地搜索 `@easyops-cn/docusaurus-search-local`（无需 Algolia） |
| 部署 | 同域名子路径 `baseUrl='/docs/'` → `https://example.com/docs/` |

## 一、初始化步骤

本工程已用以下方式创建（无需重跑，仅作说明）：

```bash
# 1. 创建 Docusaurus（经典 TypeScript 模板）
npx create-docusaurus@latest sql-logic-docs classic --typescript

# 2. 进入工程
cd sql-logic-docs

# 3. 安装本工程额外依赖：本地搜索 + Mermaid
npm install --save @easyops-cn/docusaurus-search-local
npm install --save @docusaurus/theme-mermaid
```

> 当前 `package.json` 已固化上述依赖，直接 `npm install` 即可。

## 二、标准命令

```bash
# 安装依赖
npm install

# 开发启动（端口 3005，路径 http://localhost:3005/docs/）
npm run start

# 类型检查
npm run typecheck

# 打包构建（产物输出到 build/，已带 /docs/ 前缀）
npm run build

# 本地预览构建产物（端口 3005）
npm run serve

# 清理构建缓存（构建异常时优先执行）
npm run clear

# 自动为新文档补写 heading id
npm run write-heading-ids
```

### 侧边栏如何自动生成

`sidebars.ts` 使用 `type: 'autogenerated'`，遍历 `docs/`。每个目录的 `_category_.json` 控制显示名与顺序，文档 frontmatter 的 `sidebar_position` 控制篇内顺序。**新增 `.md` 文件即自动出现在侧边栏，无需改代码。**

### docs-only 路由

`docusaurus.config.ts` 中 docs 插件 `routeBasePath: '/'`，意味着文档即站点根：

- 首页：`https://example.com/docs/`（对应 `docs/index.mdx`，`slug: '/'`）
- 文档：`https://example.com/docs/getting-started/installation`

这样配合 `baseUrl='/docs/'` 不会出现 `/docs/docs/...` 双前缀。

## 四、部署

### 子路径模式（默认）

```bash
npm run build    # baseUrl='/docs/'，产物自带 /docs/ 前缀
# 将 build/ 同步到服务器，Nginx 用 alias 挂载到 /docs/
```

Nginx 见 [nginx/docs-subpath.conf](nginx/docs-subpath.conf)。

### 子域名模式

```bash
# 1. 改 baseUrl 为 '/'
#    docusaurus.config.ts → baseUrl: '/'
# 2. 重新构建
npm run build
```

Nginx 见 [nginx/docs-subdomain.conf](nginx/docs-subdomain.conf)。

### CI

`MustBeTheSQL/.github/workflows/deploy-docs.yml`（位于仓库根，非本目录）：push 到 main 且 `sql-logic-docs/**` 变更时触发，构建后上传产物并部署到 GitHub Pages（自带 self-hosted rsync 注释模板）。

### 开发模式：与 client 同端口访问

本工程独立运行在 `:3005`，但通过 `sql-logic-client` 的 Vite proxy，开发时可直接用 `http://localhost:3000/docs` 访问，与生产路径一致：

```ts
// MustBeTheSQL/sql-logic-client/vite.config.ts → server.proxy
'/docs': { target: 'http://localhost:3005', changeOrigin: true }
```

启动方式：先启 docs（`cd sql-logic-docs && npm run start`），再启 client（`cd ../sql-logic-client && npm run dev`），访问 `http://localhost:3000/docs`。

## 五、部署注意事项

| 陷阱 | 原因 | 解决 |
| --- | --- | --- |
| **baseUrl 陷阱** | `baseUrl` 是构建期常量，改了必须重新 `build` | 子域名模式务必 `baseUrl:'/'` 后重构建 |
| **静态资源 404** | 用了绝对路径 `/img/x.png` | 用相对引用 `img/x.png`，Docusaurus 自动加 baseUrl 前缀 |
| **双 /docs/docs/ 前缀** | 子域名模式忘改 baseUrl | 见上 |
| **Nginx alias vs root** | `root` 不剥离前缀，导致路径错 | 子路径用 `alias`，SPA fallback 写 `/docs/index.html` |
| **缓存不更新** | HTML 被强缓存 | HTML 用 `no-cache`，hash 资源用 `immutable` |
| **iframe Swagger 跨域** | 不同源 | Nginx 反代 `/api/`、`/swagger-ui/` 到后端（见 subpath.conf） |

## 六、常用修改

- 改主题色：`src/css/custom.css` 顶部 `--ifm-color-primary-*`（同步硬编码的 `#5b7fd9` 渐变与 `rgba(91,127,217,...)`）。
- 改 Logo：替换 `static/img/logo.svg` + `favicon.svg`。
- 改导航：`docusaurus.config.ts` → `themeConfig.navbar`。
- 加文档：在 `docs/<分类>/` 放 `.md`，写 `sidebar_position` frontmatter。
